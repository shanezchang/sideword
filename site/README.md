# Sideword website

English: https://sideword.vercel.app/ · 中文: https://sideword.vercel.app/zh/

Two pre-rendered pages and a small progressive-enhancement script. No framework
runtime, functions, database, account or learning-data API. Vercel serves
the generated `dist/` directory. Node is needed to build, not to browse.

```sh
cd site
npm ci
npm run build
npm run dev
```

Browser tests: `npx playwright install chromium`, then `npm test`.
For production browser checks, intercept `/_vercel/insights/**` and statistics
collectors before navigation; do not manufacture pageviews. Keep local tests on
an isolated port (`PORT=...`, matching the test runner URL).
Regenerate share/icon PNGs with `node render-assets.mjs`; regenerate the vector
brand from the repository root with the command in `scripts/render_brand.py`.

## Content and release updates

Edit `content.mjs` for both languages, sample words and release links. Update the
software version in `build.mjs` alongside the installer URL; avoid implying the
terminal app has an English interface or a licensed complete IELTS dictionary.
`styles.css` owns tokens and responsive rules. Brand rationale: `DESIGN.md`.
Maple Mono v7.9 is self-hosted for all web typography, including the terminal demo,
code and IPA (with platform fallback for missing glyphs). Latin is variable;
Chinese uses real 400/600/700 subsets generated from this site's text. Sources,
OFL, coverage, SHA-256 and regeneration instructions: `public/fonts/README.md`
and `scripts/subset-maple.py`. The build uses committed WOFF2 assets, preloads
only Latin, and sets `font-display: swap`. After changing public text, regenerate
CN coverage and the share card. The existing logo outlines and their original
notice under `docs/assets/` are retained. No third-party image assets are used.

`contactEmail` in `content.mjs` is the single product contact source:
`shanechang@agentmail.to`. Both localized footers show the selectable address and mailto alongside
GitHub Issues and the dedicated private security-report instructions. No web mail
form or automated response is added.

## Deployment

Vercel project `sideword`, scope `shanes-projects-025e82ba`, repository root directory
`site`, framework Other, `npm run build`, output `dist`. No application secrets are
required. Never commit `.vercel/` or `.env*` files generated by the CLI.
Production hostname is `sideword.vercel.app`. `SITE_URL` is an optional build-time
override for a future custom domain; update canonical URLs and sitemap together.

Check the explicit owner/project with `vercel project inspect --non-interactive`
before deployment. GitHub `main` is the production source once connected.
The production alias is configured to wait for `quality`, `verify` and all six
Python/OS `test` matrix jobs. Verify all results against the deployment source SHA
and read back the formal alias after release; a READY build alone is insufficient.
The macOS matrix uses `macos-15`: GitHub retired `macos-14` on 2026-11-02.
When a runner label changes, replace the corresponding Vercel checks with the
new `source.externalCheckName`, retaining all six matrix checks and their
production alias blocking stage. Add the replacements before removing the old
IDs, after the new jobs pass and before merging. Inspect with
`vercel project checks sideword --scope shanes-projects-025e82ba --json`;
`vercel project checks add/remove` manages these checks. The PATCH API cannot
change a check's source.
Keep check names aligned with branch protection; do not force-promote a failed or
pending check. Record the previous production deployment ID before releasing,
then verify both `/` and `/zh/`, font responses and rendered text after promotion
or rollback. Roll back with `vercel rollback <previous-deployment-id>` in the
explicit project scope, then read back the formal alias; restore automatic
assignment deliberately on the next approved release. The website rollback
does not change the pinned native release or any local learning database.
For a manual CLI deployment, run from the **repository root**, not `site/`, because
the Vercel project's root directory is already `site`. The root `.vercelignore`
excludes local environments, generated packages, credentials and test artifacts.

## Search visibility

Both languages have their own static HTML, self-canonical URLs, reciprocal hreflang
and x-default, descriptive titles, descriptions and SoftwareApplication JSON-LD.
`robots.txt` allows crawling and points at `sitemap.xml`. The sitemap lists only
canonical pages. Social cards and favicon are local assets; content requires no JS.

No fabricated reviews, ratings or Google indexing promises. Search Console uses
the URL-prefix property `https://sideword.vercel.app/`, verified by the public HTML
meta tag in `build.mjs`. Keep this tag on future deployments to retain ownership.
The submitted sitemap is `https://sideword.vercel.app/sitemap.xml`.
Serving crawlable pages, verification and submission do not guarantee indexing.
No domain purchases are required.

## Website analytics

Dashboard: https://vercel.com/shanes-projects-025e82ba/sideword/analytics

The official, pinned `@vercel/analytics` browser module is copied at build time.
Only the production hostname loads it. DNT and GPC disable collection; page URL
queries and fragments are removed before sending. There are no learning events,
accounts, cookies added by this integration, or terminal-app telemetry. The demo
works if analytics is blocked. Update `analytics.js` when changing domains.

The current Hobby plan includes 50,000 events/month across the team and a one-month
reporting window. It does not include custom events: command copies, GitHub clicks
and release-link clicks are **not** measured. Do not manufacture pageviews to
simulate click events. A release visit or asset download is not a completed install.
No paid upgrade is enabled. Check current limits before changing the integration:
https://vercel.com/docs/analytics/limits-and-pricing

Review visitors, pageviews, referrers and devices after real traffic arrives.
Export reports periodically from the dashboard if longer history is needed; past
traffic cannot be recovered. Automated tests must not spoof real visitors.

Authenticated, read-only CLI reporting from the repository root:

```sh
vercel project inspect --non-interactive
vercel metrics vercel.analytics.page_view.count --since 24h --group-by requestPath --format=json
vercel metrics vercel.analytics.page_view.count --since 7d --group-by referrerHostname --format=json
```

An empty response means no reported data for that query, not proof that nobody
visited: reporting delay, browser privacy settings and blockers affect collection.
Search impressions and search clicks belong in Search Console, not this report.
